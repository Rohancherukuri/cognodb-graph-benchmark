COGNODB GRAPH BENCHMARK - SETUP, START, STOP
==============================================

This file is the quick-reference version of the "Setup" / "Running the
benchmark" sections in README.md. Read the README for the full picture
(why these platforms, fairness rules, results template); this file is
just the command sequence.


0. PREREQUISITES
-----------------
- Python 3.10+
- Docker + Docker Compose
- Outbound internet access (to snap.stanford.edu, and to whichever
  regions your CognoDB / Neo4j Aura instances are provisioned in)
- Free accounts on:
    * CognoDB Cloud   -> https://console.cognodb.com/signup
    * Neo4j AuraDB     -> https://console.neo4j.io


1. ONE-TIME SETUP
-------------------
  cd cognodb-graph-benchmark
  python -m venv .venv
  source .venv/bin/activate          (Windows: .venv\Scripts\activate)
  make setup                         # pip install -e ".[dev]"
  cp .env.example .env

  Now edit .env and fill in:
    COGNODB_URI, COGNODB_PASSWORD          (from the CognoDB console,
                                             shown once at instance
                                             creation - save it immediately)
    NEO4J_AURA_URI, NEO4J_AURA_PASSWORD    (from the Neo4j Aura console)

  Leave the MEMGRAPH_*, ARANGODB_*, DGRAPH_* values as-is; they already
  point at the docker-compose services started in step 2.


2. START THE SELF-HOSTED COMPARISON DATABASES
-----------------------------------------------
  make infra-up
  (equivalent to: bash scripts/start_infra.sh
   equivalent to: docker compose up -d memgraph arangodb dgraph)

  This starts Memgraph, ArangoDB, and Dgraph in Docker, each capped to
  0.5 vCPU / 256 MB RAM to match CognoDB's free-tier resource envelope.
  Give it ~10 seconds to finish initializing before running the benchmark.

  Check they're up:
    docker compose ps


3. PREPARE THE DATASET
-------------------------
  make dataset
  (equivalent to: benchmark dataset prepare --source snap --target-edges 300000)

  Downloads and samples the SNAP soc-Pokec social network to
  data/processed/{nodes.csv,edges.csv,manifest.json}. If SNAP is
  unreachable, this automatically falls back to a seeded synthetic graph
  (clearly labeled in manifest.json) so the harness stays runnable -
  but the real submission should use the real SNAP sample whenever
  internet access allows it.


4. RUN THE BENCHMARK
------------------------
  make bench
  (equivalent to: benchmark bench run --platform all)

  Runs every enabled platform (config/platforms.yaml) through the full
  workload sequence: clear -> index -> load -> warm-up -> 1/2/3-hop
  traversal -> point lookup -> indexed lookup -> aggregation -> mixed
  read/write sweep at 1/10/40 concurrent clients -> footprint.

  Results are written to results/<platform>.json as they complete.
  One platform failing does not stop the others - failures are recorded
  as caveats in that platform's JSON file instead.

  To run just one or two platforms while iterating:
    benchmark bench run --platform memgraph --platform arangodb


5. BUILD THE REPORT
-----------------------
  make report
  (equivalent to: benchmark report)

  Reads results/*.json and writes results/REPORT.md - a single markdown
  file with every required metric in a table, ready to paste into
  README.md's Results section.


6. STOP / TEAR DOWN
-----------------------
  make infra-down
  (equivalent to: bash scripts/stop_infra.sh
   equivalent to: docker compose down)

  Stops and removes the Memgraph / ArangoDB / Dgraph containers. Data
  inside them is not preserved - that's intentional, so the next run
  starts from a clean, comparable state.

  To also wipe local dataset + results and start completely fresh:
    make clean


7. RUNNING THE HARNESS ITSELF IN DOCKER (OPTIONAL)
------------------------------------------------------
  Instead of a local venv, you can run the CLI inside a container:

    docker compose --profile runner build benchmark
    docker compose --profile runner run --rm benchmark dataset prepare --source snap
    docker compose --profile runner run --rm benchmark bench run --platform all
    docker compose --profile runner run --rm benchmark report

  This uses the same .env file and mounts ./data and ./results so output
  lands in the same place as a local run.


8. RUNNING THE UNIT TESTS
-----------------------------
  make test
  (equivalent to: pytest -q)

  Exercises the orchestration logic (batching, percentile math,
  concurrency, failure handling, report generation) against an in-memory
  fake adapter - no live database credentials required. This is also
  what CI runs on every push (.github/workflows/ci.yml).


TROUBLESHOOTING
------------------
- "dataset not found" when running `benchmark bench run`
    -> run `make dataset` first.

- Connection refused to memgraph/arangodb/dgraph
    -> `make infra-up` and wait a few seconds; check `docker compose ps`
       and `docker compose logs <service>`.

- CognoDB / Neo4j Aura auth errors
    -> re-check COGNODB_PASSWORD / NEO4J_AURA_PASSWORD in .env; both
       platforms show the password only once at instance creation, so a
       lost password means recreating the instance.

- Port already in use (7688 / 8529 / 8080 / 9080)
    -> another process (maybe a previous run) is using that port; stop it
       or edit the port mapping in docker-compose.yml.
